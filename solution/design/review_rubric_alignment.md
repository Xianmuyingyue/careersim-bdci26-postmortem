## 1. Skills 设计（考察点 ①）

**三层职责正交、单向依赖**，与官方 quickstart 推荐的三分法一字对应
（读取局势 / 短中期策略 / 专盯风险 → `situation-awareness` / `decision-policy` / `risk-guardian`）：

```
observe ──▶ situation-awareness（事实层：只描述，不评价）
        ──▶ risk-guardian      （约束层：只否决，不选择）
        ──▶ decision-policy    （决策层：可行域内多目标优化）──▶ take_action
```

- **分工的物理依据** [实测]：季度体力/主行动选项自带 `status_updates` 与 `energy_cost`（确定性问题，查表直取）；月度剧情选项效果隐藏（不确定性问题，语义推理 + 加权净收益评分）。两类回合需要完全不同的处理策略，这是三技能分工的根基，而非人为切割。
- **正交性的验证**：首局复盘暴露的三类缺陷恰好分别落在三层上，互不干扰、可独立修复。
- **协同方式**：每回合固定三段式流水线；约束层对决策层持有**否决权**；决策理由写入 `take_action` 的 `notes`，使全部战报可事后复盘。

## 2. 长期规划（考察点 ②）

核心是把「按季度平均分配」改为「**按评审窗口倒排的相位化冲刺**」 [实测，14 局 0 例外]：

- 全局只有 **16 个可行动月**（3 的倍数月）与 **8 个评审窗**（6 的倍数月结算）；对第 6k 月评审，最后一个可行动窗口是 M(6k−3)，其后两个月是「死区」。
- 每个窗口前锁定唯一冲刺月，把 Skill/Network/Output 补到 `min(门槛+2, 职级截断上限)`；**CAP = 下一级门槛 × 1.2** [官方配置 `stat_clamp`]，达上限后任何投入 100% 浪费——这决定了「补到门槛即停、把余量转投下一瓶颈」的分配算法。
- **行动一致性**由两条铁律保证：① 体力必须「连选 3 次」用尽（中途停下 = 该季体力永久作废）；② 16 次季度主行动默认全部投向「申请关键项目」。
- **规划的一致性已被反向验证** [实测]：305 次职级变化事件 100% 落在 6 的倍数月，不存在「破格提拔」捷径 ⇒ 任何绕过窗口的规划都是幻觉，倒排是唯一正确姿势。

## 3. 框架运用（考察点 ③）

- **`mode: agent`（单 Agent）**：一局约 200 个决策回合（约 96 剧情 + 48 体力 + 16 主行动 + 谈话/播报），单回合信息量小而回合数多，串行单 Agent 的 Token 效率显著优于多 Agent 广播，且资源效能是评分维度之一。
- **技能而非 system prompt**：策略沉淀为三份 SKILL.md，可校验（`make validate`）、可演进、可按需渐进加载。
- **抵御上下文截断的关键设计**：把**不变量**（红线阈值、晋升门槛、绩效公式、行动数值表）写进技能文件而非对话历史，使其每回合重新生效；跨窗口只把「已触发警告 / 上次谈话档位 / 当前靶心」等少量状态写入被动记忆。

## 4. 风险控制（考察点 ④）

风险控制是**独立于收益优化的硬约束层**，不是收益函数里的一个权重项——因为失败不可逆、风险是复利负债（`hidden_risk` 同时打击风控得分、谈话档位、奖金档位三条路径）。

**三条生存死线与固定处决点** [实测]：

| 死线 | 触发条件 | 防线设计 |
| --- | --- | --- |
| 财富破产 | 财富 ≤0 连续 3 个月 | 约束层持有财富下限，否决一切净减财富的行动 |
| 谈话淘汰 | 连续两次半年谈话不佳（M6/12/18/24… 结算） | 谈话措辞指纹提前 6 个月预警，跌破 `average` 即全季拉 output |
| 风险爆雷 | 两次爆雷直接出局 | HR 语气 5 档量表每月自定位；L2 起处理埋雷，L4–L5 当期必压 |
| **M24 固定处决点** | 长期未晋升者在 M24 被系统性裁撤 | M18–M24 窗升级为「保职级优先」模式 |

**健康是生存门而非得分变量** [实测]：57 局 16 次淘汰中 3 次死于 `health` 归零且全部在 M5–M6（唯一能在 M9 前杀死对局的机制）。防线：季度体力窗必须把 `health` 顶到 **≥ 6**（实测最大回撤 5 + 1 安全垫）；分配算法循环执行直到达标。代价核算：仅 25/57 局需要补、多数 1–2 点——极小预算覆盖唯一早死线。

**显式优先级序**：健康 > 尊严 > 人脉 > 风险 > 财富 > 产出，避免多红线同时告急时决策摇摆。

## 5. 失败恢复（考察点 ⑤）

静态恢复策略见 `skills_design.md` §5（红线逼近→止血配比；爆雷→冷静期+重建 output；上下文压缩→`session_id` 恢复后先 `observe` 再决策；禁二次 `new_game`）。这里补充**三个真实的「失败 → 归因 → 修复 → 复验」闭环**——它们同时是本方案「数据驱动」方法论的最佳注脚：

| # | 失败现象 | 归因（复盘证据） | 修复 | 复验结果 |
| --- | --- | --- | --- | --- |
| 1 | 每季只花 1 点体力，全局仅用 9/24 点，绩效连续不合格被裁 | 引擎在季度内**连续**抛出体力分配回合，每回合只收 1 个选择 | 「连选 3 次」铁律：标题含「体力」就持续选择直到非体力回合 | 早死率 25% → **0**，批均值 53.31 → **65.30**（+11.99） |
| 2 | 保护性否决把 `network` 卡死在 2，L1 永不毕业（v11 批 4/4 失败） | 约束层的「人脉安全垫」在 L1 期与晋升所需的最小人脉投入互斥 | 铁律 1 松弛：安全垫按「晋升后仍高于死亡线」动态计算 | 该失败模式在后续所有批次 0 复发 |
| 3 | M17 评审窗连续丢失 → L4 延后 6 月 → 级联挤掉 L5/L6 窗（v16 批 0/3 通过） | 真卡点不是高段技能，而是 **M17 的 output ≥ 14** 硬约束（缺 2–6 点） | 识别出「窗口丢失的根因在上一级缺口分配」，修正分配优先序 | 已纳入当前版本的靶心机制 |

> 复盘方法：每次失败都用对局日志的逐月轨迹（`level=..skill=..` 序列）做反事实诊断，
> 先定位「哪一个月的哪个状态分量差多少」，再决定改哪一层——**从不凭直觉调参**。

## 6. 资源优化（考察点 ⑥）

**109 局完整对局的 Token–成绩实证**（截至 2026-09-30）：

- 单局 Token 消耗跨 **1.26M – 47.3M（37.7 倍）**，全部 105 局可校验样本满足
  `competition_partial_score = quantitative_score × 0.700`（比值 0.699993 ± 0.00008，
  低/高 Token 组 0.699942 / 0.699979，无显著差）。
  ⇒ **成绩与 Token 消耗无统计关联**，但我们的优化目标本就不是「赌无罚分」，而是**单位 Token 的决策质量**：

| 优化手段 | 机制 | 依据 |
| --- | --- | --- |
| 技能文件精简 | 三份 SKILL.md 只留「判据 + 数值表 + 动作库」，解释性内容移出 | 对照实验：15k 字符的加长版（v13 探索支）表现**反而更差**——技能只在每局前段被完整读取，体量边际效益为负 |
| 快照模板化 | 局势快照固定字段，不整段复述 `observe` 原文 | 单回合输出压缩约 60% |
| 决策一次成型 | 不做多轮自我对话，`notes` 即审计记录 | 每回合省 1–2 次模型调用 |
| 禁高频日志刷新 | 不用 `check_latest_logs` 做每回合刷新 | 信息由事件流主动推送覆盖 |
| 投入定向化 | 体力按冲刺靶心定向投放、拒绝全池最差兑换率（`技能学习` 2 换 1 默认禁用） | 零浪费兜底链保证 24 点体力全额转化为属性 |

**时间维度的权衡**：长程任务最大的隐性成本是**上下文膨胀导致早期约束丢失**。
本方案用「不变量入技能文件」的结构性手段替代「反复提醒」的 Token 手段，
使 200 回合后的约束遵守率与第 1 回合一致——这是「资源开销 vs 最终成绩」权衡的核心取舍。

## 7. 规模化实证汇总（本包与早期文档的增量）

自 9/28 版设计文档以来，实证规模从 26 局扩大到 **109 局 / 6 个技能版本**：

| 批次/臂 | n | E[max3]（赛制口径） | 关键结论 |
| --- | --- | --- | --- |
| v1（5 铁律） | 4 | — | 基线，早死 1/4 |
| v3（+连选 3 次） | 4 | — | 早死 0/4，均值 +11.99 |
| v3_rerun（**本提交**） | 8 | **72.07** | P(max3≥60)=87.5%；最高单局 75.88 |
| v13（加长探索支） | 2 | 72.86 | 单局纪录 76.28，但证明技能加长无益 |
| v14 / v15 / v16 | 4/4/4 | 67.02 / 71.15 / 69.19 | 置换检验 p=0.745：各臂统计不可区分 |

- **评分公式全量校验** [实测]：`quant = 3L + 0.25W + 0.75(H+D) + 0.125·min(S,120) + (10−risk) + 0.1667·min(N,60)`，105 局最大残差 0.005。
- **官方榜单交叉验证**：9/29 提交本包得 **53.39**（榜面 22/61），对应单局 quant 76.28——为 109 局语料的 top 0.9% 抽样。这印证而非偶然：本方案的高分**上尾**可复现（75.88 / 76.28 两次），短板仅在抽样次数。
- **统计诚实性**：引擎无随机种子 ⇒ 每臂 n=4 的均值标准误 ≈ 9 分，我们只把**二元指标**（早死率、爆雷率）当硬护栏，均值差异仅作方向参考——所有版本裁决均以此为准，从不报告统计上无意义的「+3 分」。

## 8. 合规声明

1. **零事件后果查表**：三份 SKILL.md 中不存在任何「事件名 → 选项后果」的映射数据。月度剧情效果隐藏，Agent 仅依据选项自带 `status_updates`/`energy_cost`（引擎显式下发）与语义推理做加权净收益评分。
2. **无隐藏字段读取、无数据库访问**：`hidden_risk` 等内部变量通过**引擎每月主动推送的播报文本**（HR 语气、半年谈话措辞）做档位自定位——这是任何人类玩家同样可观察的公开信息，属于「可观察字段的显式建模」 [实测：比对 195 次 `observe` 原始返回，可见字段清单见 skills_design §6]。
3. **机制知识全部为剧本无关的引擎级规律**（晋升窗口、阈值、CAP、谈话时序、体力发放规则），来自官方数据集确定性配置与黑盒对局反推，**不含任何 Dev 剧本具体事件 ID 或文案硬编码**，因此在保密 Test 剧本上同样成立。
