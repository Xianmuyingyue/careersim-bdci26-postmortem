## 二、M10 的 CI 两步：为什么这么选，错在哪

### 当时的状态
```
M10 seq351 决策前：output=3  network=3  skill=9  health=10  level=L1
```
三维**全部顶在 CAP(L1)** = (3, 3, 9)。这不是"接近达标"，是**一格不剩**。

### 第 1 步：投入 2 周完整搭建（Δ output −2 / network −1）

技能为什么会选它：普查**混合均值**显示

| 选项 | 混合净收益 | 看起来 |
|---|---|---|
| #1 投入 2 周搭建 | **−0.725** | 更优 ✅ |
| #2 维持手动 Review | −1.20 | 更差 |

⇒ 按「选扣得最少的」规则，选 #1 是**符合当时规则的**。

**但按「是否已顶格」分层后，方向完全相反**：

| 状态 | n | #1 净收益 | #1 明细 |
|---|---|---|---|
| L1·三维未满 | 4 | **+0.50** | output −1.5 / network −1.0 / **skill +3.0** ✅ |
| L1·满 1 维 | 6 | +0.33 | skill +2.67 |
| L1·满 2 维 | 1 | **−3.00** | skill 收益**全部消失** |
| **L1·满 3 维（本局）** | **6** | **−3.00** | output −2.0 / network −1.0，**零收益侧** |

**机制**：CI#1 的收益侧 **100% 在 skill（+2.15 均值）**。skill 已顶格 CAP(L1)=9 ⇒ 增量被引擎丢弃 ⇒
**只剩扣分项**，从 +0.50 直接翻成 −3.00。而 #2 在 L1·满3维是 −1.00（skill −1、health −2）。
⇒ **在顶格状态下，#2 比 #1 好 2 点，与混合表的结论正好反过来。**

**它的收益是什么**：`risk=0`（播报里对方"笑"，反应最好）+ wealth +0.2。
⇒ 是买反应/降险，但在零余量的 L1，用 output/network 付账付不起。

### 第 2 步：维持严格阈值（Δ output −1 / network −2）

| 选项 | n | 净收益 | 明细 |
|---|---|---|---|
| #1 维持严格阈值（本局选的） | 16 | **−1.188** | output −0.81 / network −1.75 / skill +1.38 |
| #2 放宽阈值渐进 | 19 | **+1.474** | output +1.0 / network +1.47 / skill −1.0 |

⇒ 差 **2.66 点**，且 #2 的 skill −1 在顶格时可以用体力「技能学习」免费补回。
**这是纯失误，没有任何截断借口。**

### 两步合计
`output −3 / network −3`，把 (3,3,9) 打成 (0,0,9) ⇒ **M11 评审 output=1 < 3 ⇒ 未晋升**。

## 三、低调避险：它到底有没有收益

### 真实收益（n=135，主行动位）

| 维度 | 均值 | 非零回合占比 | 说明 |
|---|---|---|---|
| health | **+0.63** | 85/135（63%） | **这是它唯一的真实收益** |
| wealth | +0.415 | 55/135（41%） | ⚠️ **是工资，不是它的收益** |
| output/network/skill | **0** | 0 | 三维恒为 0 |

**wealth 为什么看起来有 +0.415**：主行动回合**总是当月最后一个回合**，而月末工资结算就落在这一回合
（135 次主行动**全部**带 `工资` 标记）。41% 的回合 wealth +1 正好对应 L1 月薪 0.3、约 3.3 个月进 1 点。
⇒ **用户看到的"4 次里有 1 次 wealth +1"是工资入账的巧合，不是低调避险给的。**

### 关键对照：L1 三维全满时，其它主行动也是 0

| 主行动（L1·满 3 维） | n | 净收益 | 其它 |
|---|---|---|---|
| #8 低调避险 | 65 | **+0.00** | health **+0.72** |
| #1 申请关键项目 | 31 | **+0.00** | wealth +0.13 |
| #4 申请岗位轮岗 | — | 无样本（顶格时没人选） |

⇒ **在 L1 三维全满时，主行动位所有选项的三维增量都是 0**（全被截断）。
低调避险能拿到 +0.72 健康，反而是**唯一还有正收益的选择**。
⇒ 它**不是主要失血点**，复盘文档把 4 次主行动都算成"作废"是夸大的。

### 那为什么会选它（决策链根因）

`decision-policy` §2.2 的分配算法：
```
g(x) = max(0, min(TH(next,x)+2, CAP(level,x)) − x)
④ g 全 0 → a.埋雷(若风险≥1) b.技能学习 c.允许保留体力
```
L1 三维全满 ⇒ `g` 全 0 ⇒ 落到 ④；主行动位**没有**埋雷、也没有技能学习 ⇒ 落到 ④c ⇒ **映射成「低调避险」**。

**真正的病灶**：算法把「没有缺口」等同于「可以不行动」。
但在 L1，`CAP == 门槛` ⇒ **"没有缺口"恰恰是最脆弱的状态（零余量）**，掉 1 点就判负。

## 五、补丁方案（5 条，可直接写成 SKILL 规则）

### 补丁 1 · 分层边际值表（Cap-Aware Ledger）★ 最高优先级

**问题**：现行普查表主键 =「选项」，均值跨职级/跨顶格状态混合 ⇒ CI#1 显示 −0.725，
掩盖了「未满 +0.50 / 已满 −3.00」这两极。

**做法**：主键改为「选项 × 顶格维数」。决策时先算
```
full = #{ dim ∈ {output, network, skill} : x[dim] ≥ CAP(level, dim) }
```
再查 `full` 对应层；该层样本 < 4 才退回混合值，并标注"证据不足"。

**已扫出全池 23 项截断敏感项**（L1 未满 vs 已满，净收益差 ≥ 1.8），典型：

| 事件·选项 | 未满 | 已满 | 差 |
|---|---|---|---|
| 远程客户返工汇报 #1 复盘+原型 | +4.00 | 0.00 | 4.00 |
| 带病同事 #1 关心并顶班 | +4.00 | 0.00（仍扣 health −1） | 4.00 |
| 客户 Demo 突发 Bug #1 切备用环境 | +4.00 | 0.00 | 4.00 |
| 竞标答辩 #1 扬长避短 | +3.86 | 0.00（仍扣 health −1） | 3.86 |
| 主行动 #1 申请关键项目 | +3.75 | 0.00 | 3.75 |
| **CI 第一步 #1 投入搭建** | **+0.50** | **−3.00** | **3.50** ← 唯一"转负" |
| 健康检查返回错误状态 #1 立即修 | +3.00 | −0.25 | 3.25 |

⇒ **绝大多数投入型选项是"已满时归 0"（白干），CI 第一步是"已满时转负"（倒扣）**。
前者浪费一个机会，后者直接毁窗口，**必须分级处理**。

### 补丁 2 · 截断转负门禁（Cap-Loss Gate）★ 无需查表，纯逻辑

规则写成不依赖数据的形式（合规友好，不引用引擎内部符号）：
```
若某维已顶格（该维当前值 == 该职级下的可观察上限），则：
  凡"收益主要落在这一维"的选项，其收益必然被丢弃 ⇒ 按"只剩扣分项"评估。
  若扣分项落在零余量维（output / network，在 L1 上 CAP == 晋升门槛）⇒ 禁止选择。
```
本局直接命中：CI#1 收益全在 skill，skill 已顶格 ⇒ 只剩 `output −2 / network −1` ⇒ 禁止。

### 补丁 3 · 零余量 / 暴露窗守卫（Zero-Margin Guard）

```
margin(dim) = CAP(level, dim) − TH(next_level, dim)
L1 的 output / network：margin = 0   ← 零余量
```
当 `margin == 0 且 x[dim] == TH` ⇒ 该维进"零余量"：
1. drama 选项一律按「**哪项扣得少**」排序，不按"哪项补得多"（已有规则，保留）；
2. **新增**：长链事件**整条链**进入零成本模式——**第一步扣了之后，后续步不得沿用同一路线**
   （M10 就是第 1 步扣完、第 2 步继续硬核）；
3. **新增**：主行动位**不得**选择"不行动/无产出"类（见补丁 4）。

### 补丁 4 · L1 锁定 → 晋升优先模式（Escape-L1 Mode）

**判据**：`level == L1 且 full == 3`（三维全部顶格）
**证据**：此时所有主行动三维增量均为 0（申请关键项目 +0.00、低调避险 +0.00）
⇒ **继续在 L1 投入是零回报**，唯一出路是升到 L2 解锁更高的可观察上限。

规则：
1. 判定 L1 锁定后，**唯一 KPI = 在下个评审点（month % 6 == 5）让三维在评审瞬间达标**；
2. 所有 drama 切"零成本模式"，**禁止任何会扣 output / network 的选项**（含降险型）；
3. 降险改走**体力位的「处理历史埋雷」**（三维不可观察，不占用零余量维）；
4. 主行动位：优先能扩大可观察上限的行动；若都不能，选 **health**，因为那是唯一还能落袋的
   ⇒ **低调避险在这种情况下是合理的，不要禁**。

### 补丁 5 · 低调避险的正确门禁（不是禁用，是条件化）

它唯一的收益是 `health +0.72`。因此：
- `health < 6` ⇒ 值得选（安全垫规则，M3 末要 health ≥ 6）；
- `health ≥ 6` ⇒ 健康的边际价值为 0，此时若**三维未满**，应选「申请关键项目」（未满时 +3.75）；
  若**三维已满**，其余选项也都是 0 ⇒ **低调避险可接受**，不是主要失血点。

⇒ **把"禁用低调避险"改成"health ≥ 6 且三维未满时禁用"**。
（复盘文档原规则「主行动位禁用低调避险」过于粗暴，本局 4 次里有 3 次 health 已 ≥ 7，
但当时三维全满，换成申请关键项目也是 0 ⇒ 改了也不会变好。）
