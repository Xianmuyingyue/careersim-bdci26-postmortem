## 2 三个可压缩面（按杠杆排序）

### 2.1 面 A：技能体积本身（19.4%）—— 本方案主战场

单轮占比 77,619 / 406,335 = **19.1%**；Σprompt 占比 **19.4%**。两个口径一致。

### 2.2 面 B：装饰与历史（占技能 33%，零/低风险）

| 类别 | 现状字符 | 说明 |
| --- | --- | --- |
| **版本沿革文字** | **14,387** | 含 `v10a~v10e`／`旧版`／`已被证伪`／`新增`／`修正`。**对当下决策零价值** |
| **实证论证过程** | **15,662** | `实测 57 局…`／`全池 974…`／`依据`／`lift`。只需保留结论 |
| 加粗星号 `**` | 4,898 个字符 | 绝大多数是**装饰性强调**，无信息量 |
| 表格分隔行 + 竖线 | ~3,600 | 45 行分隔行 + 表格管道符 |

### 2.3 ★★ 面 C：技能丢失后的「回流成本」（比体积更严重）

**实测链条**：

```
[142] context.compact_boundary  "Conversation compacted"   ← 技能全文在此被丢弃
[143] context.compact_summary   11,194 字符                ← 摘要（不含技能细节）
[67]  grep  "T(x)|CAP|门槛表|5.1|晋升门槛"  → 只回 211 字符（没搜到）
[69]  read_file  MessageSummaryOffloader_*.json  →  36,198 字符
[72]  read_file  MessageSummaryOffloader_*.json  →  28,134 字符
```

**解读**：技能被压缩掉后，Agent **丢失了晋升门槛表**（原本在 `situation-awareness` §5.1），
于是去 `grep` —— **没搜到**（211 字符），只好**读两个历史卸载文件**，共 **64,332 字符**。

⇒ **压缩的代价不止"省不下来"，而是会产生二次成本**：丢失规则 ⇒ 回溯 ⇒ 又 64K 字符进上下文 ⇒ 又加速下一次压缩。
⇒ ★★★ **这是比技能体积更大的杠杆**：如果能减少"规则丢失"，可直接砍掉这 64K。

**同时这也是一条重要因果推论（待验证）**：
一局 48 个月约需 700 次 LLM 调用 ⇒ 约 4 次压缩 ⇒ **技能只在首个 1/4 局有效**，
之后 Agent 靠**残存记忆 + 零散回溯**决策。
**这可能是"死亡多发生在中后期"的一个解释。**（列为假设 H1，见 §5.3）

## 4 预期收益（算式与数字）

设技能体积缩减比例 `r`，技能在 prompt 中占比 `p = 19.4%`：

```
Σprompt 降幅   = p × r = 0.194 × r
单轮 prompt 降幅 = 同理（压缩前区间内）

r = 0.30（第一步）⇒ Σprompt −5.8% ｜ 单轮 185,419 → 178,177（−3.9%）
r = 0.45（第二步）⇒ Σprompt −8.7% ｜ 单轮 185,419 → 170,205（−8.2%）
```

⚠️ **注意这里出现了一个反直觉结果**：因为**压缩后技能不再参与上下文**（§1.3：压缩点之后 `ctx` 从 406K 掉到 11K），
所以"技能变小"对**全局 Σprompt** 的节省会被**稀释** —— 只在前 1/4（85/173 次调用）真正受益。

**用实测数字重算（更准）**：

| 方案 | 压缩前区间（85 次调用）单轮 | 该区间 Σprompt | 全局 Σprompt | 全局降幅 |
| --- | --- | --- | --- | --- |
| 现状 | 77,619 / 406,335 | 6.21M 技能部分 | 32.08M | — |
| r=0.30 | 技能 54,333 | 4.35M | 30.22M | **−5.8%** |
| r=0.45 | 技能 42,700 | 3.42M | 29.29M | **−8.7%** |

★★ **但"单轮 prompt 峰值"的降幅更大**：
压缩触发点是**固定阈值**（406,335 字符）。技能小 32K ⇒ **达到阈值所需轮次更多**
⇒ 压缩间隔从 85 次延长到约 **93 次（+9.4%）** ⇒ 压缩次数从 4 次降到约 3.7 次。

### ★★★ 真正的收益在面 C（§2.3）

若规则不再丢失（例如核心规则更精简、更易存活于摘要），可省掉 **64,332 字符**的回溯读取 ⇒
**额外 Σprompt −2.0%**，且**避免"后期无规则"的行为退化**（价值远大于 token 节省）。

**两条加起来**：Σprompt 约 **−11%**，单轮峰值 **−8%**，压缩次数 **−9%**。

> **诚实结论**：**技能压缩能减约 10% 的上下文压力，不是"减半"。**
> 因为技能本来就只占 19%。想要更大的降幅，必须同时处理"规则丢失→回溯"这条链。

## 5 无损验证方案（不跑对局，可离线一次跑完）

> 核心思路：**压缩是"改写"不是"删规则"**，因此可以用**守恒式检查**证明规则未丢。

### 5.1 规则条目守恒（强校验）

提取每个技能里所有**可枚举的规则标识**，压缩前后必须**一一对应**：

```python
# 校验清单：压缩前 vs 压缩后，四个集合必须完全相等
1. 硬约束编号      r'^\|\s*\*{0,2}(\d+[a-f]?)\*{0,2}\s*\|'      # RG 约束 1..15
2. 章节编号        r'^#{2,4}\s*[0-9]+(?:\.[0-9]+)*'              # §5.12 / §12.3 …
3. 跨层引用        r'§[0-9]+(?:\.[0-9]+)*'                        # 所有引用目标
4. 数值常量        r'\d+(?:\.\d+)?'  的全部取值集合               # 门槛/CAP/阈值/系数
```
**通过条件**：① 集合差为空；② 每条的**关键谓词**（禁止/必须/一票否决）在压缩后仍存在。

### 5.2 关键数字白名单（防止"顺手改掉阈值"）

把下列常量做成白名单，压缩前后 diff 必须**完全一致**：

| 类别 | 示例 |
| --- | --- |
| 晋升门槛 / CAP | `8 / 3 / 3`、`×1.2`、`int()` |
| 健康线 | `≥ 6`、`−4`、`M3/M4/M5` |
| 风险线 | `≥ +2 拒收`、`≥ 5 爆雷`、`≥ 3` 红灯、`R̂` 阈值 |
| 赌本分层 | `k = 2/1/0`、`安全垫 ≥ 3 / 0..2 / < 0` |
| 顺位表 | 六桶 `30/57/701/116/38/32`、`0%/14%/16.5%/27.6%/31.6%/81.2%` |
| 零工具区 | `472/472`、`187/187` |

### 5.3 行为等价性抽检（离线问答）

对压缩后的技能，让另一个模型回答一组**预置问题**，答对率必须 100%：

1. `health = 5、季内第 1 月`，安全垫是多少？允许选哪几桶？
2. 约束 13 与约束 14 谁先执行？为什么？
3. `hidden_risk` 读数 3 时，`ΔRisk = +2` 的选项能否选？
4. M6 评审看的是哪个月末的状态？三维门槛是什么？
5. 六桶顺位表的第 3 桶是什么？它的 `P(ΔH<0)` 是多少？
6. 长链整链风险预算的判据是什么？

**通过条件**：全部答对，且**答案与压缩前版本完全一致**。

### 5.4 假设 H1 的验证（需要 1 局，可选）

> H1：技能在首次压缩后丢失 ⇒ 中后期决策退化。

**验证方法**：对已有对局日志，按"压缩边界"切分，
统计**压缩前 vs 压缩后**的平均决策质量指标（如 `ΔO`、违规率、`health` 净变化）。
若压缩后显著变差 ⇒ H1 成立 ⇒ 面 C 的优先级要提到压缩之上。

**这个验证不需要跑新对局**，用现有 77 局日志即可。

## 6 红线：绝对不能压的东西

| 类别 | 为什么 |
| --- | --- |
| ★ **约束条目与编号** | 跨层引用（`risk-guardian` 约束 N）依赖编号稳定；改号会静默断链 |
| ★ **裁决链顺序** | 顺序本身是规则（v10e 的教训：赌本分层必须排在截断转负之前） |
| ★ **阈值数字** | 门槛/CAP/爆雷阈，一个都不能变 |
| ★ **否决关系** | "一票否决"的语义不可弱化为"建议" |
| ★ **`description` 里的激活键** | 它决定技能是否被读；压缩时**只能同向缩短，不可丢机制名** |
| 合规表述 | 不写引擎内部符号与本地路径 |

```
首次压缩点              = 85 次 → 87 次调用      =  +2.6%
```

**结论：无风险压缩（A+B+E）的全部空间就是这个量级 —— 约 −2.3% 的上下文压力，不是 §3 设想的 −30%。**
理由（§2.1 早已预判）：技能只占 Σprompt 的 19.4%，**其余 80.6% 是事件流与工具结果**，压技能的天花板由占比锁死。

### 9.5 本次修复的 4 处「压缩副作用」（★ 教训）

B 类删除"旧版…已删除"这类**纯变更日志句**时，会把它后面**依赖该句作先行词的句子变成悬空句**：

| 位置 | 症状 | 修法 |
|---|---|---|
| RG §埋雷段 | `实测 7 个通关局平均只投 3.7 点（预算的 20%），说明这条配额…` —— "这条配额"失去所指 | 句首补 `埋雷不设固定配额（旧版曾要求"每 2 季 1 次 + 硬性预留 16–20 点（35–40%）"）：` |
| DP §体力表 | `而"埋雷次数与爆雷零相关…"` —— 以"而"开头但前句已删 | 句首补 `埋雷不设固定配额：实测只投到 3.7 点，且` |
| SA §5.6 | `> （实测：埋雷只投到预算的 20%…）` —— 括号句失去主句；且**删掉了指向 `decision-policy` §2.2 的跨层引用** | 恢复为 `> ★ 降级理由：资源分配只由 \`decision-policy\` §2.2 的 \`g(x)\` 决定，…` |
| DP §瓶颈真相 | 表格前的主句 `旧版写「M24 投 output…」…否定了前半段：` 被删，表格裸奔 | 补回一句同义主句 |

⇒ **方法论增量：删"变更日志句"前，必须先检查它是否是后续句子的先行词，或是否承载跨层引用。**
