# v16「高段解锁」臂 · 四局复盘（2026-09-30）

## 一、假设与设计

**假设**：`skill` 的**评分**在 120 封顶，但**晋升门槛不封顶**（L6 需 130、L7 需 170）。
v3_rerun 的铁律 3「`skill ≥ 120` 后 `ΔSkill` 记 0 分」会让 Agent 在 120 之后主动停投 skill，
从而把职级永久锁在 L6。若拆掉这条自我设限，可望把 L6 从 M42 提前到 M36，进而解锁 L7@M48。

**设计**：`analysis/ab/v16` = v3_rerun 拷贝，**只改 decision-policy**（RG/SA md5 与 v3_rerun 一致，隔离变量）。
DP md5 `faa85702`，12,583 字符（基线 9,389，+3,194）。

| # | 补丁 | 内容 |
|---|---|---|
| A | 铁律 3 | 「`skill ≥ 120` → 记 0 分」改为「`skill ≥ 120` **且已达下一级 skill 门槛** → 记 0 分」 |
| B | §三修正 1/3 | 引入 `SKILL_GATE`（L6:130 / L7:170 / L8:210）；`skill ≥ 120 但 < SKILL_GATE` 时 ΔSkill 权重恢复 0.40 |
| C | 铁律 1 | 高段松弛：`skill ≥ 120` 后配比门禁由 `network ≥ skill/2` 改为 `network ≥ 下一级 network 门槛` |
| D | 新增 §七 | 高段解锁协议：UNLOCK 三条改写 + 双靶心（L6@M36 = 132/48/34；L7@M48 = 172/64/47）+ output 绩效保底红线 |
| E | §五 | 目标基准 `L6 @ 月 42` → `L6 @ 月 36` |

## 四、★ 假设被证伪：UNLOCK 从未真正触发

UNLOCK 的触发条件是 `skill ≥ 120`。四局里：

- RUN2 全程最高 skill **110**，从未触发；
- RUN3 卡死 L1（skill 9 = CAP），从未触发；
- RUN1 / RUN4 只在 **M47–M48 才摸到 120–124**，此时 L6 的评审窗早已错过。

**⇒ 补丁作用在一个这些局根本到不了的区间。** 评测窗结算时的实际数字：

| RUN | M47（L5→L6，需 s130/n45/o32） | M41（L4→L5，需 s90/n30/o22） |
|---|---|---|
| 1 | s117 n49 o33 → **skill 缺 13** | s97 n36 o26 → ✅ |
| 2 | （仍 L4） | s83 n36 o26 → **skill 缺 7** |
| 4 | s120 n51 o30 → **skill 缺 10、output 缺 2** | s108 n36 o25 → ✅ |

L6 门槛 skill 130，实测 M47 只到 117–120，**差 10–13**。这与 105 局包络（M36 最高 123）一致，不是这四局的偶然。

## 五、★ 真正的卡点被这次实验反证为更早的两道坎

把 v16 三局完赛局与 v3_rerun 八局按评审月逐窗对齐（评审在 `month%6==5` 月首结算）：

**坎 1 —— M17 的 L3→L4（需 s35 / n18 / o14）**

| 臂 | M17 通过率 | 落榜时的缺口 |
|---|---|---|
| v16 | **0/3** | output 缺 6 / 缺 2+net 缺 2 / （已掉到 L2） |
| v3_rerun | 3/6（o15、o16、o15 通过；o11、o9、o5 落榜） | 同样是 output |

**坎 2 —— L4→L5 的 skill 断层（35 → 90，+55）**

v16 三局全部消耗 **3 个窗**（M29 ❌ → M35 ❌ → M41 ✅），因为坎 1 把 L4 推迟到 M24，
等于少了一个完整成长期；v3_rerun 最好的三局是 M23 ❌ → M29 ❌ → M35 ✅（L5@M36），
剩下的时间刚好够在 M47 冲到 129–148 拿到 L6。

**⇒ 级联**：M17 丢窗 → L4 延 6 月 → L5 延到 M42 → L6 无窗 → L7 无从谈起。
**L6 能否提前到 M36，取决于 M17 那次 output 有没有到 14，而不是取决于 120 之后要不要继续投 skill。**

## 六、结论

1. **v16 判负，假设证伪。** 拆掉「skill 120 停投」没有带来任何收益——因为这个区间在实战中到不了。
2. **维持 v3_rerun 提交**（E[max3] 73.47 vs 69.19；4/8 达 L6 vs 0/4）。
3. **v17 若还要做，靶心必须换到 M17**：把「L3 段 output 保底」写成硬约束
   （进 L3 当季起每季度至少保证 `output ≥ 16`，且评审前一月禁一切 `ΔOutput < 0`），
   而不是继续在 L5/L6 段做文章。
4. **体量教训再次印证**：DP 从 9,389 → 12,583 字符（+34%）而 RG/SA 不变，
   点估计全面下滑，与既有结论「体量边际效益为负、技能只在首个 ~1/4 局被完整读取」一致。
   后续补丁应优先做**减法**。
5. `solution/skills` 已恢复为 v3_rerun（DP `175c9d21` / RG `906480f1` / SA `0b7a0625`）。
