> 数据源：引擎 `emulator_logs/<session>.log`（权威）+ `score_report.json` + agent 自述 notes。
> 复现脚本：`analysis/v83_risk_promo.py`、`analysis/notes_by_month.py`、`analysis/state_trace.py`、
> `analysis/find_miss_reason.py`。
> ⚠️ 口径：引擎日志的 `Month N` 比技能口径 M 早 1（日志 M5 = 技能 M6 评审窗），本文统一用**技能口径**。

## 0. 先厘清一件事：v8_3 → v8_5 不是「改动导致下降」

两者是**同一套策略**（v8_5 = v8_3 + 合规措辞），逐行 diff 只有措辞差异、零策略改动。
所以 v8_3（73.68 / 73.79）与 v8_5（通关局均值 67.42）之间的差距**本身属于单局方差**。

真正的问题是：**样本从 2 局放大到 7 局后，策略里两个「本来就没被保证住」的环节暴露了。**
v8_3 那两局是恰好蒙对（前 3 窗恰好全中、恰好没爆雷），不是策略做对了。

## 1. 晋升节奏：**没掌握好，且在 M18 窗有系统性缺陷**

### 1.1 硬数据（引擎 [promotion] 行）

| 臂 | 局 | 前 3 窗命中 | M18 窗（L3→L4） | 晋升时点 |
|---|---|---|---|---|

| v8_3 | 164951Z | **3/3** | ✔ M18 | M6 M12 **M18** M36 M48 |

**前 3 窗命中率：v8_3 = 6/6（100%）；v8_5 = 11/21（52%）。**
**M18 窗（L3→L4）：v8_3 = 2/2；v8_5 的 5 个通关局里只中了 1 个（1/5）。**

### 1.2 根因 = network 缺口（agent 自己的诊断，非我推测）

- `232221Z`：「**M18 未晋升（L3，network 7 远低于 L4 门槛 18**，且谈话提示仍在观察名单）」
- `192500Z`：「**M18 未晋升（N12<18，仅缺人脉）**」
- `205025Z`：M15 时已算出「唯一剩余缺口是 network（10→18, g=8）」→ M18 窗未过
- `201004Z`：连 M6 窗都是「**M6 因 N2 未过**」（L1→L2 需 network ≥3）

**network 门槛的跳变是全游戏最陡的一条**：

| 窗 | 需要 network | 晋升税 | 备注 |
|---|---|---|---|
| M6（L1→L2） | ≥3 | −1 | |
| M12（L2→L3） | ≥7 | −3（升迁节奏过快） | L2 段 CAP(network) 仅 8 ⇒ **最多囤到 8** |
| M18（L3→L4） | **≥18** | −2 | L3 段 CAP=21 才放得下 18 |

⇒ **M12 晋升那一刻 network 会被扣掉约 3（7~8 → 4~5），然后要在 6 个月内冲到 18，即实际需要 +13~14。**
体力侧每季 3 点、`人脉维护` 1 点/+1 ⇒ 两个季度最多 +6。**剩下 +7~8 必须全部来自剧情选项。**
这是数学上极紧的约束——而策略里**只有 skill 有跨级囤量机制（铁律 17④），network 没有**。

### 1.3 为什么「先易后难」会系统性地漏掉 network

`g(network)` 在 L3 段永远是最大的（缺口 11~14），而「先易后难 = 取 g 最小且 >0 的一维」⇒
**network 恒排在 output / skill 之后**，只能在「其他维全达标」之后才拿到体力。
实测 `205025Z`：「Q6体力…**唯一缺口** network(16→18)，N16→17 / N17→18」——等到它成为唯一缺口再补，
已经离 M18 只剩不到一个季度。

### 1.4 迟一窗的代价（可直接换算成分数）

M18 漏 ⇒ L3→L4 落到 M24 ⇒ L4→L5 从 M30/M36 顺延到 **M42** ⇒ 终局 L5 而非 L6。
- 职级项：L5 = 50 vs L6 = 60（×0.30）⇒ **每局 −3.0 分**，5 个通关局里 4 局吃到 ⇒ **均摊 −2.4**
- 财富项：L5 月薪 1.0 只领 1 个月、L4 月薪 0.7 段拉长 ⇒ 通关局财富 29.1 vs 35.1（−6.0 raw）⇒ **−1.5 分**

## 2. 爆雷控制：**没做到，而且方向恰好搞反了**

### 2.1 硬数据

| 臂 | 爆雷局数 | 爆雷月（技能口径） | 终局 hidden_risk |
|---|---|---|---|
| v8_3 | **0/2** | — | 2 / 0 |
| v8_5 | **3/7** | **M30、M36、M41** | **5 / 0 / 1 / 5 / 5** |
| v8_4 | 1/2 | M23 | 5 / 0 |

三个关键事实：

1. **3 次爆雷全部落在 M42 之前**（M30 / M36 / M41），而 M42 之后 0 次。
2. **三次全部发生在我方自己定义的「冲刺+评审」区间**：M30 ∈ [M27,M30]、M36 ∈ [M33,M36]、M41 ∈ [M39,M42]。
3. **3 局终局 hidden_risk 停在 5 = 爆雷阈值**。爆雷后 risk 归零又攒回 5，意味着**随时可能二次爆雷 = 直接出局**（`信任危机end`）。通关是运气。

对照铁律 16③ 的本意是「**M42 前谨慎、M42–M48 终局才允许激进一次**」——实际是反的：
该谨慎的区间爆了 3 次，该激进的那个窗一次也没用（M42 后爆雷 0 次）。

### 2.2 根因也在策略文本里，不是执行走样

v8_3/v8_5 的 `decision-policy` 铁律 17② 原文：

> 评审窗内（r∈{0,1,2}）任一维对下一级门槛的缺口 ≤ 2 时，该维优先级置顶……**不得被「健康恢复 / 技能学习 / 埋雷」挤出**（§2.2④ 兜底链在小缺口存在时跳过）

**「埋雷」被明文列为可以被挤掉的对象，而它的作用域正好覆盖 r∈{0,1,2} = 评审窗 = 爆雷发生的那三个区间。**
条款与现象完全同源。

实测印证（`232221Z`，M30 窗冲刺季 M27）：

> M27体力(SPRINT r=3, 余3)。L4→L5(M30)缺口：network 29→30(仅+1)、output 16→22、skill 52→90(主瓶颈)。
> 按§2.2③先易后难，先补最小正缺口 network：人脉维护→N30 达门槛。**余 2 点转 skill 瓶颈。体力 3/3 用尽。**
> … M31：**先选 4 处理历史埋雷(HiddenRisk−1)压风险。**

⇒ 冲刺季 **3/3 体力全给了缺口，0 点给风险**；等到 M31（HR 提示风险之后）才被动清 1 点，
而阈值是累积 ≥5、单次清雷只 −1 ⇒ 追不上。

### 2.3 可观察量分辨率不足，是第二层原因

风险只以**4 档提示**暴露（绿/黄/橙/红 = 约 0/1/2/3–4），而爆雷阈值是 **累积 ≥5**：
在「橙」档时真实值可能已是 4，剧情再来一次 +2~+3 的注入就直接跨过 5。
⇒ **靠「看到橙灯再清」的被动策略，天生追不上**。必须在黄灯（≤1）就往回压，或者干脆**每季固定留 1 点给埋雷**（成本可控：每季 −1 risk = 每半年 −2，足以抵消常规累积）。

## 3. 分数差额的完整拆解（用实测反算）

v8_3 通关局均值 73.74 vs v8_5 通关局均值 67.42，差 **−6.32**：

| 维度 | v8_3 | v8_5 | 换算分差 |
|---|---|---|---|
| 职级（×0.30） | L6 / L6 | L5×4 + L6×1 | **−2.4** |
| 财富（×0.20，×1.25） | 35.1 | 29.1 | **−1.5** |
| 风险控制（0.10，100−raw×10） | raw 1.0 → 90 | raw 3.2 → 68 | **−2.2** |
| 身心健康（×0.15，×5） | 17.5 | 18.4 | +0.7 |
| 专业能力（÷1.2，120 封顶） | 均封顶 | 均封顶 | 0 |
| 同事关系（×1.667，60 封顶） | 均封顶 | 均封顶 | 0 |
| 合计 | | | **≈ −5.4**（余下为方差） |

**⇒ 两个问题几乎解释了全部差距：职级 2.4 + 风险控制 2.2 + 财富 1.5 = 6.1 分。**

## 4. 结论（回答「这些有做到么」）

| 问题 | 结论 | 证据强度 |
|---|---|---|
| 晋升节奏掌握得好吗 | **没有。** 前 3 窗命中率 100% → 52%，M18 窗是系统性漏点（1/5） | 强（引擎 [promotion] 行 + agent 自述诊断一致） |
| M42 前做到谨慎风控吗 | **没有，而且搞反了。** 3 次爆雷全在 M42 前、全在评审窗附近；3 局终局 risk 停在阈值 5；M42 后的「激进豁免」一次未用 | 强（引擎 [warning] 行 + 冲刺季体力分配实录 + 条款原文同源） |

两个问题的机制都指向**同一类缺陷**：策略在「评审窗」里为了拿分而**主动牺牲了 network 的长期储备和风险防线**，
而这两项恰好是**跨窗复利项**（network 决定下一级能否晋升、risk 决定会不会一击归零）。
即：**策略过度优化了「本窗四维达标」，忽略了「下一窗的起点」。**

## 5. 待议（本次只分析，未改动任何技能文件）

1. **铁律 17② 的例外表应补上「埋雷」**：现文写「不得被…埋雷挤出」是明确的负向激励来源。
   最小修法：把「需当季埋雷」从可牺牲项里移出，或在评审窗内**固定预留 1 点体力给风险**。
2. **铁律 17④ 的囤量对象应扩展到 network**：network 是 M18 窗的唯一瓶颈，且有 −2/−3 晋升税，
   当前策略只对 skill 做跨级囤量，network 完全依赖剧情被动积累。
3. **「先易后难」在 L3 段应对 network 破例**：`g(network)` 恒最大 ⇒ 恒排最后 ⇒ 结构性补不上。
   可考虑对「有晋升税 + 门槛翻倍」的维改用「按缺口/可用窗口数」的紧迫度排序，而非绝对缺口。
4. 复核 v8_4（00:10 版）并未真正改善爆雷率（1/2 vs 3/7，样本都太小），
   其「冲突裁决优先级」那半段思路正确，但被「前 3 窗 skill 顶 CAP」那半段拖累——两半需拆开验证。
