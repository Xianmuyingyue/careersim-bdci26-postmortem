## 1. 数据源与方法

**引擎状态快照的唯一可靠来源** = `outputs/九问/<run_dir>/events-*.jsonl`。
每行是 `{"seq","ts","kind","payload"}`；`tool_result` 内嵌一段**被转义两层**的引擎 JSON：

```
{"current_state":{"time":{"current_month":N},"status":{health,dignity,skill,network,level,duration_in_level,output,wealth,energy},
 "simulation_flags":{...}},"current_event":{...},"choices":[...],"events":"..."}
```

**抽法**：`line.replace('\\"','"')` 后用 `json.JSONDecoder().raw_decode()` 从每个 `{"current_state":{` 起平衡解析。

**三条踩坑（已固化进脚本）**：

1. ⚠️ `grep '"current_month"'` 命中 0——原文是 `\"current_month\"`。
2. ⚠️ **同一快照会在日志里重复渲染 4 次**，去重键必须含「结算月」：`(结算月, 档位, 金额, 当时职级)`；只用后三项会把 **L1 上 M18 与 M24 的同一个 `D/−0.6`** 合并（曾据此得出「M12 仍 L1 ⇒ 100% 被裁」的**错误**结论，真实为 6/23）。
3. ⚠️ **选项的 `notes` 里常含转义内层引号**（如 `选\"按事实打B\"`），用 `replace('\\"','"')` + `json.loads` 会静默丢参数 ⇒ 需捕获 `JSONDecodeError` 并回退解析。**本报告第 9 个样本 `222709Z` 最初就是这样被漏掉的。**

**本轮的"对齐"方法**（本轮最大方法学增量）：
> 不再只看「月末快照」，而是把 **最后一次 `M(6k−1)` 快照** → **评审快照** 之间的
> **所有 `take_action` 调用**都抽出来（称为**未渲染动作**），再与 Δ 做差分归因。
> 实测 56 局里 **50 局恰有 1 条未渲染动作**、5 局 0 条、1 局 2 条。

## 2. M6 晋级判定的完全分离

### 2.1 四格矩阵

| 口径 | 达标且晋级 | 达标未晋 | 不达标却晋 | 不达标未晋 | 准确率 |
|---|---|---|---|---|---|
| 用 **`M5` 月末快照**预测 | 25 | **12** | **5** | 14 | **69.6%** |
| 用 **评审快照**预测 | **29** | 0 | 1 | **26** | **98.2%** |

- 评审口径的**唯一例外**：`20260926T022719Z`——M5 末 `S9 O3 N3` 达标 ⇒ 成功晋升 L1→L2，
  但**同帧遭爆雷**（"之前的隐患好巧不巧一起炸了，最近半年的工作都打了水漂"）⇒ `output` 回滚到 **0**。
  ⇒ 属**爆雷通道**，不是绩效/门槛通道。
- ⇒ **M6 的"随机感"100% 来自「`M5` 末 → 评审点」这一步的状态漂移，而不是门槛的可变。**

### 2.2 未晋级局的缺口分解（以评审快照为准，n = 26）

| 缺口 | 局数 |
|---|---|
| 只缺 `network` | **12** |
| 只缺 `output` | 7 |
| 缺 `output` + `network` | 6 |
| 缺 `skill` + `network` | 1 |

**全部是 1–2 点的极窄缺口，没有一局是大缺口。** ⇒ 分配算法已把三维推到"恰好踩线"，
**缺的不是量，是余量**。

### 2.3 为什么是"零余量"——L1 的截断结构

```
CAP(L1,x) = floor( TH(L2,x) × 1.2 )   ⇒  skill int(8×1.2)=9 ／ output int(3×1.2)=3 ／ network int(3×1.2)=3
TH(L2)    =                             8 ／ 3 ／ 3
⇒ 截断余量 = +1 ／ +0 ／ +0            ★ output 与 network 余量恒为 0
```

对比 L2：`CAP = 21/6/7` vs `TH(L3) = 18/5/6` ⇒ 余量 **+3/+1/+1**（依旧很薄）。
**余量随职级放大**（L3 起 `+7/+2/+3`）⇒ **L1 是唯一"零缓冲"职级，L2 是"薄缓冲"**。

### 3.1 两条可用的负向语义族（实测，`n=12`）

| 语义族 | 关键词 | 实测效果 | 出现次数 |
|---|---|---|---|
| **原则族** | 承认 / 如实说出 / 按事实 / 拒绝 / 提出异议 / 守边界 / 要求合规交接 | **扣 `network`（−1 ~ −2）** | 6 |
| **投入族** | 接下 / 深入准备 / 投入 N 周 / 牵头搭建 / 写正式信 / 当天补救 | **扣 `output`（−1 ~ −3）** | 5 |

**★ 12/12 零例外：Agent 笔记里写着"补 N / ΔN≥0 / 合规无风险"的选项，实际全部扣了 N 或 O。**

⇒ 三条推论：
1. **剧情选项没有"纯增益项"**，每一项"得到"都配一项"失去"（`+N` 配 `−O`、`+O` 配 `−N`、`+S` 配 `−H`）。
2. **触顶不对称**：维度已到 `CAP` 时，**增益被截断丢弃、扣减全额生效** ⇒ 该维上任何选项的期望值 **≤ 0**。
3. ⇒ **触顶时应按"哪项扣得少"排序，而不是"哪项补得多"**；对 `ΔN`/`ΔO` 的**负向风险赋权远高于正向**。

## 4. 「升迁震荡」的触发条件（新机制，已确定化）

评审文案里若出现：

> 「晋升通知：…您已从 Lx 晋升至 Ly。」**「升迁节奏过快，原有人脉圈还没消化你的新身份——协作摩擦上升，办公室侧目增多。」**

则晋升后**追加**一次 `Network −3 / Dignity −1`（施加在**晋升判定之后**，所以不会反过来影响本次晋升）。

### 4.1 触发条件（全量 186 次晋级事件）

| 与上次晋级的间隔 | 震荡率 |
|---|---|
| **首次晋级**（无上次） | **0 / 49 = 0%** |
| **6 个月**（连续两窗都晋级） | **58 / 58 = 100%** |
| 12 个月 | 0 / 43 = 0% |
| 18 个月 | 0 / 34 = 0% |
| 24 个月 | 0 / 2 = 0% |

**⇒ 等价判据：两次晋升间隔 `< 12 个月` ⇒ 必触发；`≥ 12 个月` ⇒ 绝不触发。**

### 4.2 操作含义

- **`L1→L2`（M6 或 M12 的首次晋级）永远干净**，不扣 `network`。
- **`L2→L3` 及以后：只要上一窗也晋级过（间隔 6 个月）就必吃 `Network −3`。**
  而 `L3` 门槛 `network = 6` ⇒ **一次震荡就吃掉一半门槛**。
- ⇒ **不能"为了躲它放慢晋升"**（`CAP` 锁死成长上限的损失远大于 3 点人脉），
  但**必须把它当已定价成本写进 `network` 预算**（目标值 +3）。
