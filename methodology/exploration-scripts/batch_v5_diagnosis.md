## 二、四条新机制发现（本轮最重要产出）

### ★★★ 发现 1：`performance_score` 的完整公式与 **L1 绩效天花板 = 3 < 出局线 4**

`perf` 是**计算字段**（`.venv/.../failure_conditions.py:155`），面板与播报都不给，必须自算：

```
stat_term = (min(high, low×2.0) + max(0, high − low×2.0)×0.3) / 15      # low/high = min/max(skill, network)
out_term  = output / 10
lvl_term  = 职级多项式  →  L1 +2.00 / L2 +3.00 / L3 +2.00 / L4 0.00 / L5 −4.00 / L6 −8.00 / L7 −12.00
mercy     = (current_month ≤ 12 且 perf < 4) → perf 强制 = 4
```

| 职级 | 满配满算 `perf` | 晋升门槛 | 出局线 |
| --- | --- | --- | --- |
| **L1**（skill 9 / network 3 / output 3） | `0.46 + 0.30 + 2.00 = 2.76 → **3**` | 3 | **4** |
| L2（21 / 7 / 6） | `1.07 + 0.60 + 3.00 = 4.67 → 5` | 4 | 4 |

**⇒ 在 `L1` 段，"能晋升"（≥3）与"不算绩效不佳"（≥4）永远不可能同时成立。**
前 12 个月的 mercy 是唯一护盾。

`consecutive_bad_performance` 规则自带 **HP = 2**，计数器每次评审只要 `perf < 4` 就 +1 并扣血
（触发后归零，附带 `network −1 / dignity −3`）。
**⇒ 名称是"连续 2 次"，实为"累计 2 次"。**

### ★★★ 发现 2：`M11`（第 11 月末评审）是硬生死线

20 局实测：

| 情形 | 局数 | 结果 |
| --- | --- | --- |
| `M5` 未过、`M11` 过线 | **7** | **全部存活**（只是慢 6 个月） |
| `M11` 未过 | **2** | **全部被裁**（`042320Z` D/24 月、`190936Z` E/24 月） |

**因果链**：`M11` 未过 ⇒ 进入 M13–M23 仍为 L1 ⇒ `perf` 恒为 3 < 4 ⇒ M17 吃 `−2HP / N−1 / D−3` ⇒ M23 再吃一次 ⇒ 出局。
**「慢 6 个月」可以承受，「漏掉 M11」不能承受。**

### ★★★ 发现 3：评审读取的是 **`M(6k−1)` 月末状态**；`M(6k−2)/M(6k−1)` 是零行动预算的「暴露窗口」

月份形状（`analysis/month_shape.py`，全批一致）：

```
month % 3 == 0 → [剧情×3] [体力×2~3] [主行动×1]
month % 3 != 0 → [剧情×3]
```

评审落在 6 的倍数月边界 ⇒ **评审月的前两个月（M4/M5、M10/M11 …）是 6 个纯剧情回合，零行动预算。**

实测证据：`042320Z` 在 M5 末两个剧情选择里被扣掉 `N −1 / O −1`（`S9 N3 O3 → S9 N2 O2`）⇒ M5 未过；
该局随后在 M6 用「人脉维护×2」把 N 拉回 3，**但评审已结算，补救完全无效**（局内 Agent 自述"评审在进入 6 的倍数月时已结算"）。

**可行性**（Dev 全池 412 节点 / 974 选项）：

| 量 | 值 |
| --- | --- |
| `P(ΔNetwork ≥ 0 且 ΔOutput ≥ 0)` | 58.6% |
| **「节点至少存在一个 `ΔN ≥ 0 且 ΔO ≥ 0` 的选项」** | **93.4%** |

⇒ 「暴露窗口只选 `ΔN ≥ 0 且 ΔO ≥ 0`」在 **93.4%** 的节点上可行。

## 三、两局失败的完整因果链

### 失败 A：`20260925T042320Z` ——「L1 死循环」+ 暴露窗口失守

```
M5 末：N2 O2（差 N−1 / O−1）→ M5 评审未过        ← 破坏点：M5 最后两个剧情选择各扣 N/O 一点
M6：用「人脉维护×2」把 N 拉回 3 → 但评审已结算，无效
M11 末：N2（差 N−1）→ M11 评审未过               ← ★★★ 生死线失守
M12–M23：在 L1 停留，perf ≡ 3 < 4
M17 末评审：吃 consecutive_bad_performance 第 1 击（−2HP / N−1 / D−3）
M23 末评审：仍差 N−1；随后吃到第 2 击 → 炒鱿鱼
终局：24 月 / D 级 32.06 / 体力只用了 21/48 点（技能学习 0 次）
```

**关键归因**：全程 95 个回合里，`network` 在 1–3 之间反复抖动（`CAP(L1,N)=3=门槛`，**余量恒为 0**），
而 Agent 把体力投给了「处理历史埋雷×4」「健康恢复×6」，**没有一次用主行动「建立导师关系」补 N**。
**不是"缺量"，是"抖动"**——L1 段的 N/O 只能"守"，必须靠铁律 12 的暴露窗口保护。

### 失败 B：`20260925T043821Z` —— 单次高注入导致双重爆雷

```
M19：橙灯（皱眉 = 2）
M20–M22：降到黄灯（偷偷 = 1）
M23：选「拒绝转岗威胁，正面回应…」→ ΔHiddenRisk +3 → 读数 1 → 4   ← ★ 铁律 5 应在此拦截
M24：选「收集证据，向 CEO 和董事会渠道正式举报 VP 的职场霸凌」→ ΔHiddenRisk +5 → 爆雷（第 1 击）
M37：再读「生气（≥4）」；M37/M38 之间第二次爆雷 → 信任危机出局（38 月 / D 级 48.56）
```

**该局的结构与两局 A 完全同构**（M5/M11/M17 连过 + M23/M29 卡 `skill` + M35 过 L5），
**唯一差异就是风险治理**——它牺牲了整局，只为两条"语义上更正义"的选项。

**⇒ 这是本轮策略修正的最强依据：把「当下读数为黄灯」当作"安全"是错的，判据必须是「选项的 ΔRisk」。**
