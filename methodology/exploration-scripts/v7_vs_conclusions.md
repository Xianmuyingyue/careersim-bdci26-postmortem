## 一、v7 的"大决定"策略长什么样（客观复述）

v7 是三层正交技能，流水线：`situation-awareness`（事实）→ `risk-guardian`（约束，有否决权）→ `decision-policy`（决策）。

**1. 裁判标准**
- 财富是职级的影子（事件池 171 文件中 `wealth` 零命中）→ "职级 30% + 财富 20% = 同一变量"。
- 一切决策的裁判只有一句：**它能否让下一次晋升更早发生？** 副标准：是否让 `hidden_risk` 上升（每点 −1.00 终局分，唯一无替代途径的支出）。

**2. 缺口驱动分配（"先易后难"）**
- 自算 `g(x) = max(0, T(x) − x)`，`T(x)=min(TH+2, CAP)`（skill 例外可上探到 CAP）。
- 每季 3 点体力**连选 3 次**，每选一次重算 `g`；优先补 `g` 最小且 >0 的达标维：
  `output→准备汇报材料` / `network→人脉维护` / `skill→技能学习`；`g` 全 0 才转尊严或保留。
- 真相：低职级时 `skill` 的 CAP 只有 9/21/42，`g(skill)` 自动归零把体力让给 O/N；进 L4（CAP 108）才接管 → 自动复现瓶颈轮换，无需硬编码阶段。

**3. 季度主行动（耗 0 体力，每季 1 个，9 选 1）**
- 裁决：`有效补量 = Σ min(增量_x, g(x))`，取最大；平票优先 `申请岗位轮岗`。
- **明确把 `申请关键项目`(+2O/+1S/+1N) 与 `申请岗位轮岗`(+2S/+1N) 当 output/skill 主来源**；
  `skill 基本无法靠体力冲刺（2 体力=1 skill），主要来源是主行动与剧情`。

**4. 月度剧情（数值隐藏，靠语义）**
- 加权得分 `0.35ΔO + 0.30ΔN + 0.25ΔS + 0.15ΔD(+满记0) + 0.05ΔH(health≤4升0.40) − 0.60ΔR`。
- 硬性修正：① `skill≥CAP` → ΔS 权重归零；② `skill<TH` → ΔS 权重升到 **0.40**（"skill 无法靠体力补，必须靠剧情提前攒"）。

**5. 两条最高优先铁律**
- 铁律 11（M11 生死线）：L1 段 `perf` 数学上限=3 < 出局线 4，M11 必须过。
- 铁律 12（暴露窗口保护区）：`month%6 ∈ {4,5}` 只准选 `ΔN≥0 且 ΔO≥0`（93.4% 节点可行）。

**6. 风险治理（risk-guardian）**
- `hidden_risk` 同时打击四条路径（终局 −1.00/点、talk −2.0/点、奖金掉档、爆雷回写 6 月前 output）。
- **橙灯（≥2）立即排埋雷**；约束 5 把 `hidden_risk` 控制在 **≤3**（距爆雷线 5 留 2 点余量）；
  "文案词典"把任何 `ΔRisk≥+2` 的剧情选项**永远拒收**；埋雷预算 8–10 次（16–20 点，占体力 35–40%）。
- **已自我修正**："埋雷次数与爆雷零相关，总注入量与单次峰值才是自变量" → 埋雷是止损非保险。

**7. 体力层 output 来源**：`准备汇报材料`(+1O/+1D, 耗1) 而非 `高强度工作`——后者在 §2.1 明确标注 **"近乎不用"**。

## 三、结论

1. **v7 在 output/skill 来源上已和本次结论高度一致**——它早已弃用 `高强度工作` 作 output 主引擎，
   改用主行动 + 剧情。我上一轮"若 v7 把高强度工作当主引擎则严重低估主行动槽"是假设性提醒，**现已证伪（v7 没这么做）**。
2. **唯一值得你拍板的真实差异**是 `risk-guardian` 约束 5 的"余量 2 点（≤3）"是否过保守：
   v7 把**任何 ΔRisk≥+2 的剧情选项一律拒收**，而真实爆雷线在**累积 5**；
   意味着"读数 0–2 时的 +2/+3 注入"其实安全，却被 v7 放弃。
   （收紧到 ≤3 是怕首爆——首爆就回写 6 月前 output——但代价是可能错过带 +2 风险却给 +2O/+2S 的顶级剧情组合。）

## 四、给你的决策点（未改 v7，等你定）

- **A. 维持现状**（保守，≤3，凡 +2 注入即拒）：最稳，几乎不可能爆雷；但可能少拿安全剧情收益。
- **B. 改判据为"当前读数 + ΔRisk ≥ 5（或留 1 点余量 → ≥4）才拒"**：放行读数低时的 +2/+3 注入；
  更贴近真实规则、可能多拿剧情收益，但要求更精准追踪 `hidden_risk`（依赖 HR 文案解码，v7 已具备）。
- **C. 折中**：保留"橙灯立即埋雷"，把"永远拒收 +2/+3"改为"读数 + ΔRisk ≥ 4 才拒"
  （即允许 `hidden_risk ≤ 1` 时吃 +2/+3 注入）。
