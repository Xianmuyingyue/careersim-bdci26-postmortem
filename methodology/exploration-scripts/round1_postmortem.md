## 二、根因分析：晋升窗口的两次「差 2 点」失手

### 2.1 晋升只在固定窗口结算

官方 `promotion/config.json`：`schedule.on_month_modulo = 6`，即**只在第 6/12/18/24/30/36/42/48 月**做被动评审。阈值达标但错过窗口，就要再等 6 个月。

回合与月份的换算（实测）：**1 个月 ≈ 4 个回合**，窗口对应回合 ≈ 24 / 48 / 72 / 96 / 120 / 144 / 168 / 192。

### 2.2 实际达成时刻 vs 实际晋升时刻

| 目标 | 阈值 (skill/output/network/dignity) | 首次同时达标 | 实际晋升 | 判定 |

| L2→L3 | 18 / 5 / 6 / 3 | 回合 38（月 10） | 回合 44（月 12 窗口） | ✅ 窗口内 |
| L3→L4 | 35 / 14 / 18 / 3 | 回合 67（月 17） | 回合 69（月 18 窗口） | ✅ 窗口内 |
| L4→L5 | 90 / 22 / 30 / 4 | 回合 124（月 31） | 回合 141（月 36 窗口） | ⚠️ **错过月 30 窗口** |
| L5→L6 | 130 / 32 / 45 / 4 | 回合 174（月 44） | 回合 189（月 48 窗口） | ⚠️ **错过月 42 窗口** |

**关键证据（窗口前的状态快照）：**

- 第 30 月窗口（回合 ≈ 120）：`skill=88, output=20, network=36` → 距 L5 门槛仅差 **skill −2、output −2**。
- 第 42 月窗口（回合 ≈ 168）：`skill=126, output=38, network=49` → 距 L6 门槛仅差 **skill −4**。

两次均为一两个季度补量的差距。若这两次窗口命中，职级路径从「L5@36、L6@48」变为「L5@30、L6@42」，并额外获得冲击 L7 的 6 个月窗口。

### 2.3 财富为何是「职级的影子」

**核心事实：全动作池中不存在任何直接增减 wealth 的选项**（已对 `decoded_dev/action_pool` 全部 171 个事件文件——53 个长链 + 118 个短链——做全文检索，`wealth` 零命中）。

财富只有两个来源，且都由职级决定：

1. **月度基本工资**（`salary_conditions/monthly_base_salary.json`）：
   `L1 0.3 / L2 0.4 / L3 0.5 / L4 0.7 / L5 1.0 / L6 1.5 / L7 2.3 / L8 3.6 / L9 5.7 / L10 9.1`
2. **半年绩效奖金**（`half_year_performance_bonus.json`）：
   `bonus = 月薪 × 档位系数`，`S 3.0 / A 1.5 / B 0.5 / C −1.0 / D −2.0`（档位由绩效分闸值 12 / 8 / 5 / 3 决定）。

**公式验证**（复现误差 < 0.2）：
月度工资合计 33.0（按实际职级时间轴）+ 半年奖金 4.6 + 初始财富 1.0 = **38.6 ≈ 38.5 ✅**

因此：**晋升速度是唯一能同时撬动「职级 30%」与「财富 20%」这两个最大权重项的杠杆。** 升一级（L6→L7）使月薪从 1.5 升到 2.3（+53%），并使每期 A 档奖金从 2.25 升到 3.45。

## 三、次因分析：三项结构性浪费

### 3.1 技能溢出 23 点（最直接的浪费）

专业能力维度上限为 **120**，实际终值 **143**，溢出 23 点不产生任何分数。更严重的是，L6 的数值截断上限为 `L7 门槛 × 1.2 = 204`，因此这 23 点**既不能加分、也没有换来晋升资格**。对照 L6→L7 只差 `skill −27 / output −5 / network −3`：若把这 23 点技能投入 output，足以直接触发月 42 窗口的 L6 晋升。

**纠偏规则：`skill` 达到 120 后，所有偏向 skill 的事件选项与体力行动一律让位给 output / network。**

### 3.2 风险控制只拿 4/10

维度口径为 `cumulative_risk_inverted`，上限 10。本局触发 **11 次 HR 风险预警**（7 次「有点风险」+ 4 次「积攒了不少风险」）。压制手段只有体力行动 `处理历史埋雷 ×4`——本局 16 次季度主行动全部投给 `申请关键项目 ×11` 与 `申请岗位轮岗 ×5`，**从未使用过 `低调避险`**，风险侧完全靠「预警后被动补救」。

爆雷（`hidden_risk ≥ 5`）的真实代价（`failure_conditions/risk_burst.json`）：`output` 回写为 6 个月前快照、`dignity −2`、**`wealth −2`**、`risk_burst_count +1`；**第二次爆雷 = HP 2，直接出局**。注意爆雷同时扣财富——风险失控会同时打击「风险控制 10%」与「累计财富 20%」两个维度。

**纠偏规则：把 `hidden_risk` 视作不可逆债务而非可透支额度。`处理历史埋雷` 从「预警后补救」改为「每 2 个季度固定 1 次预防性执行」。**

### 3.3 绩效档位偏低（8 期中 4 期 B、1 期 C）

绩效公式（`performance_score/config.json`，Variant 4）：
```
perf = round( (min(a, b×2) + 0.3×max(0, a − b×2)) / 15 + output/10 + 职级九次多项式 ) + 谈话修正
其中 a = max(skill, network), b = min(skill, network)，softcap_ratio = 2.0
```
softcap 意味着：`skill` 超出 `network` 两倍的部分，只按 **30%** 计入绩效。本局 skill:network 在后期达到约 **143 : 57 ≈ 2.5 : 1**，已越过 2:1 拐点，**尾部 29 点技能在绩效公式里只值 8.7 点**。这是绩效档位难上 A 的直接原因，也再次指向同一处修复：给 skill 封顶、把人脉补到 skill 的一半。
