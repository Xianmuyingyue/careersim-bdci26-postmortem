## 二、死因机制：三局全是「二次爆雷」，hr 阶梯还原了完整链路

三局死局的 hr_seq 尾部都呈现同一指纹：

```
… L0_safe → L1_mild → 【L4plus_imminent】→ L0_safe(首爆回零) → … 重爬 … → L3_critical/L4plus(二次) → 出局
```

以 RUN 4（M25 死）为例：risk 从 mild(1) **单步跳到 imminent(≥4)** ⇒ 一条真实 `ΔRisk ≈ +3~+4`
的剧情选项被放行了。但 v8 的约束 5 明确「拒收一切 Δ≥+2」——它为什么没拦住？

**⇒ 因为约束 5 判的是「估计的 ΔRisk」（语义词典推断），而 Agent 看不到剧情选项的真实数值。**
真实 +3/+5 的选项若被词典估成 +1，就会在**任何版本**里被放行（v7 RUN 4、v5 的 043821Z 同一死法）。

**v8 为什么死得更多（3/4 vs v7 的 1/3）**：C1 激进版（5b：`R̂≤3` 时 +1 档放行）把风险**骑乘基线**从
v7 的 0–1 抬高到 1–3。基线越高，同一条「被低估的大注入」越容易一步越过爆雷线；
且首爆后 output 回写、缺口重开（v8 的极限速率压力加剧了补产出的急迫感），二次爆雷概率进一步上升。
B2 账本管得住「已接受的增量」，管不住「被低估的那一笔」——它是事后清理，不是事前拦截。
