## 2. ★ M6 恒为 C 的机制证明

### 2.1 实测

```
M6   样本 18   档位分布  C:18         C+D 占比 100%   职级分布 L1:18
```

### 2.2 为什么必然如此

`perf` 公式（`situation-awareness` §4.3）：

```
perf = round( stat_term + output/10 + poly(L) ) + 谈话修正
stat_term = (min(high, 2·low) + max(0, high−2·low)·0.3) / 15     low/high = min/max(skill, network)
```

L1 的三维被截断上限锁死：`CAP(L1) = (skill 9, output 3, network 3)`。

```
L1 满配（S9 / N3 / O3）：
  low=3, high=9 → capped=6, excess=3 → stat_term = (6 + 0.9)/15 = 0.46
  out_term = 3/10 = 0.30
  poly(L1) = +2.00
  perf = round(2.76) = 3   ← C 档（3–4），且 < 出局线 4
```

**⇒ 即使在 L1 把三维全部顶到上限，`perf` 也只有 3。M6 的档位没有第二个可能。**

### 2.3 精妙之处：mercy 只保护「计数」，不改变「档位」

```
mercy：current_month ≤ 12 且 perf < 4  →  perf 强制置 4
```

| | `perf = 3`（无 mercy） | `perf = 4`（mercy 生效） |
| --- | --- | --- |
| 奖金档位 | **C**（3–4） | **C**（3–4）—— **完全一样** |
| 「绩效不佳」计数 | **+1**（`perf < 4` 成立） | **不变**（4 不小于 4） |

**⇒ mercy 的价值不在奖金，而在于把 M6/M12 这两次评审从"绩效计数"里摘出去。**
这也是"M6 恒为 C 但不会因 M6 出局"的原因。

## 4. ★ 自变量识别

### 4.1 档位 × 职级 交叉表（核心证据）

| 评审点 | 职级 | 样本 | 档位分布 |
| --- | --- | --- | --- |
| M6 | **L1** | 18 | **C:18**（零方差） |
| M12 | L1 | 7 | **C:7**（零方差） |
| M12 | L2 | 10 | B:9 / C:1 |
| M18 | L1 | 5 | C:1 / **D:4** |
| M18 | L2 | 3 | B:3 |
| **M18** | **L3** | 9 | **B:9**（零方差） |
| M24 | L1 | 4 | C:2 / D:2 |
| M24 | L3 | 6 | B:6 |
| M24 | L4 | 6 | A:1 / B:5 |
| M30 | L4 | 10 | A:4 / B:6 |
| M36 | L4 | 10 | **A:8** / B:2 |
| M42 | L4 | 6 | A:4 / B:2 |
| M42 | L5 | 5 | A:1 / B:3 / C:1 |
| M48 | L5 | 8 | A:2 / B:6 |

### 4.2 量化

```
r(职级, 档位) = 0.754        (全部 115 个评审点)
r(职级, 档位) = 0.681        (仅 M12 起，97 点)

组内方差（同一职级内档位稳定性，档位映射 S=5/A=4/B=3/C=2/D=1）：
   L1: n=34  均值 1.82  sd 0.38
   L2: n=14  均值 2.93  sd 0.26
   L3: n=18  均值 3.00  sd 0.00   ← 完美锁死（18 个样本全是 B）
   L4: n=34  均值 3.53  sd 0.50   ← 组内仍有可控余地
   L5: n=14  均值 3.14  sd 0.52   ← 组内仍有可控余地
   L6:  n=1  均值 3.00  sd 0.00
```

**判读**：
1. **`L3` 的组内 sd = 0.00**——同一职级内 18 个样本**毫无差别**。这是"职级决定档位"的最强证据：
   决定档位的不是当年怎么努力，而是**当时站在哪一级**。
2. **`L4`/`L5` 的 sd 约 0.5**——这两个职级内存在可控变量，主要来自 `output`（见 §5.2）。
3. `L1` 的 sd 0.38 来自 C 与 D 的差别 —— **而 D 只出现在 L1**（§6）。

### 4.3 为什么职级是"双锁"

职级同时决定两件事，**而它们都进入 `perf`**：

| 锁 | 机制 | 作用在公式哪一项 |
| --- | --- | --- |
| **锁 1：`poly(L)`** | L1 `+2.0` / L2 `+3.0` / L3 `+2.0` / L4 `0` / L5 `−4.0` / L6 `−8.0` | 直接加减 |
| **锁 2：三维 `CAP = 门槛 × 1.2`** | L1 `(9,3,3)` → L2 `(21,6,7)` → L3 `(42,16,21)` → L4 `(108,26,36)` | 决定 `stat_term` 与 `out_term` 的**上限** |

**⇒ 停在 L1 时，锁 1 给 +2 但锁 2 把三维压到极低（stat 0.46 + out 0.30 = 0.76）⇒ perf 上限 3。
升到 L2 后，poly 升到 +3 且三维上限翻倍（stat 1.07 + out 0.60 = 1.67）⇒ perf 上限 5。**

## 5. 各职级的档位天花板（理论外推）

### 5.1 满配表

| 在职级 | 三维满配 (S/N/O) | `stat_term` | `out_term` | `poly` | **perf** | **档位** |
| --- | --- | --- | --- | --- | --- | --- |
| **L1** | 9 / 3 / 3 | 0.46 | 0.30 | +2 | **3** | **C** |
| **L2** | 21 / 7 / 6 | 1.07 | 0.60 | +3 | **5** | **B** |
| **L3** | 42 / 21 / 16 | 2.80 | 1.60 | +2 | **6** | **B** |
| **L4** | 108 / 36 / 26 | 7.20 | 2.60 | 0 | **8** | **A** |
| L5 | 156 / 54 / 38 | 8.16 | 3.80 | −4 | **8** | A |
| L6 | 204 / 72 / 54 | 10.80 | 5.40 | −8 | **8** | A |
| L7 | 252 / 96 / 72 | 14.00 | 7.20 | −12 | **9** | A |
| L8 | 300 / 120 / 90 | 17.20 | 9.00 | −16 | **10** | A |

**⇒ 每一级的档位天花板是"硬"的：在 L1 拿不到 B，在 L2/L3 摸不到 A。**

### 5.2 `output` 是唯一的「无帽线性杠杆」

`stat_term` 被软帽腰斩（`min(high, 2·low)`）且被 `/15` 压缩：
短板侧每 **+15 点** skill/network 才换来 `perf +1`。

而 `out_term = output / 10` —— **每 +10 点 output 稳定换 `perf +1`**，无软帽、无压缩。

**⇒ 这也解释了 L4/L5 的组内 sd 为何约 0.5：同为 L4，`output` 顶到 26 的局拿 A（perf 8），
只补到 20 出头的局落在 B（perf 7）。这是"同职级内唯一的可控变量"。**

### 5.3 ★ S 档在 L1–L7 数学不可达

| 职级 | 满配 perf | +谈话 good(+2) | S 档（≥12）可达？ |
| --- | --- | --- | --- |
| L5 | 8 | 10 | 否 |
| L6 | 8 | 10 | 否 |
| L7 | 9 | 11 | 否 |
| **L8** | 10 | **12** | **是（仅此一级）** |

**⇒ 终局前为"冲 S 档"投入资源是纯浪费。全游戏只有 L8 满配 + 谈话 good 才可能触及 S。**

## 6. ★ `D` 档是「停在 L1」的专属指纹

全部 8 个 `D` 档样本的职级分布：

```
M18 @L1:  D×4        M24 @L1:  D×2
（其余 2 个 C 也在 L1）
```

**所有 `D` 档 100% 出现在 L1。** 机制：L1 的 `perf` 真值 = 3，若同时
`network` 被打到 1（`low=1`），则 `stat_term` 从 0.46 掉到 0.27 ⇒ `perf = round(2.27) = 2` ⇒ **D 档**。

`perf = 2 < 4` ⇒ 评审时触发「绩效不佳」计数 +1（`network −1 / dignity −3` / HP−2）。

**⇒ 见到 `D` 档就等于看到「这一局从未离开 L1，且已进入出局倒计时」。**

### 7.1 两局早亡的直接原因：从未晋升

```
RUN 1  level_timeline = [[1, 'L1']]      ← 24 个月全程 L1，一次都没升
RUN 2  level_timeline = [[1, 'L1']]      ← 同上
RUN 3  level_timeline = [[1,'L1'],[6,'L2'],[12,'L3'],[18,'L4'],[36,'L5'],[48,'L6']]
```

档位序列：

```
RUN 1   M6:C@L1   M12:C@L1   M18:D@L1   M24:C@L1     → M24 出局
RUN 2   M6:C@L1   M12:C@L1   M18:D@L1   M24:D@L1     → M24 出局
```

**且两局的三维长期顶格**（`capped_field_months`：RUN 1 的 `L1:skill` 78 个月、`L1:network` 76、`L1:output` 66）。
**⇒ 不是补不上去，而是"顶格了也升不了级"。**

### 7.2 完整死因链

```
L1 的 CAP(network) = 3 = 门槛 ⇒ 余量恒为 0
   ↓  network 在评审瞬间掉到 2（已被历史统计：M6/M12 评审 19/37 次未过的真因）
M6 四维门挂 → 未晋升
M12 再次挂门 → 仍未晋升
   ↓  month > 12，mercy 失效
M18 仍在 L1 ⇒ perf 真值 3（若 N 被压到 1 则为 2）< 4 ⇒ 「绩效不佳」计数 = 1
M24 计数 = 2 ⇒ 炒鱿鱼end
```

**这条链与财富无关**——RUN 1/2 的财富是 6.1 / 3.1，都没有进入赤字。
**⇒ 财富守卫生效了（零 `喝西北风end`），但主死因转移到了绩效。**

## 8. 策略调整建议（按可操作性排序）

### 8.1 认清"绩效不是独立项"

`perf` 与晋升门的 `optional_conditions.performance_score` 是**同一个值、同一次评审**。
⇒ **不存在"为绩效额外投资"这回事**；唯一可控路径是**把职级抬上去**。

### 8.2 立即执行：放弃对 M6 的绩效投资

- M6 的 `C` 是 `CAP(L1)` 与 `poly(L1)` 双锁的结果，**任何策略都改不了**。
- **不要**为了"M6 拿 B"去加 `output` 或 `skill`——L1 的 `output` 上限只有 3，`skill` 上限 9，投了也溢出。
- M6 唯一值得做的事：**保住 `N ≥ 3` 与 `O ≥ 3` 以通过四维门**（这才是 M6 的真正意义）。

### 8.3 核心杠杆排序

| 序 | 杠杆 | 效果 | 可操作性 |
| --- | --- | --- | --- |
| **①** | **晋升（职级跳变）** | `poly` 跳变 + 三维 `CAP` 解锁 ⇒ 档位天花板跳一级（L1→L2 是 C→B） | ★★★ 但它是结果，靠 ②③ 实现 |
| **②** | **`output`** | **每 +10 = `perf` +1**（无软帽、无压缩） | ★★★ 主行动「申请关键项目」+2 O / 体力「准备汇报材料」+1 O |
| **③** | **`skill`/`network` 软帽平衡** | 短板侧每 **+15** = `perf` +1 | ★★ 注意：**必须补 `min` 侧才有效**（`stat_term` 用的是 `min(high, 2·low)`） |
| ④ | 谈话档位 | ±2 | ★ 被动，受 `hidden_risk` / `dignity` 影响 |

### 8.4 三条硬性结论

1. **M18 前必须离开 L1** —— 这不只是 `CAP` 问题，而是**绩效计数**问题：
   L1 的 `perf` 天花板 3 < 4，M18 起 mercy 失效 ⇒ 必然开始计数，M24 执行。
2. **别为 S 档浪费资源** —— L1–L7 数学不可达，只有 L8 满配 + 谈话 good 才可能。
3. **`D` 档是"仍在 L1"的警报** —— 一旦出现，说明该局已进入 M24 出局倒计时，
   必须立刻把一切资源压到**四维门（尤其 `network`）**上，而不是继续补绩效。

### 8.5 需要新增到技能的条目

1. **`situation-awareness` §4.3**：补「各职级档位天花板表」（§5.1）与「S 档不可达」。
2. **`decision-policy` 铁律 17③（C 档警报）**：注明「**M6 的 C 是机制性的，不是绩效门危机**」，
   避免把 M6 的 C 误判为需要修复的信号而浪费资源。
3. **`risk-guardian` 约束 4b 的复核**：验证财富硬否决是否会挤压 L1 段的 `network` 补位（§7.3 假设）。
