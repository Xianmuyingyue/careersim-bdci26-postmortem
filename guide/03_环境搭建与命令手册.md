## 二、`.env` 配置（关键）

把 `.env.example` 复制为 `.env`，只需三个变量：

```bash
API_BASE=""     # 你的模型服务地址
API_KEY=""      # 你的 API Key
MODEL_NAME="deepseek-v4.1-flash"
```

> ⚠️ **注意官方资料中的一处不一致**：
> - 官方 **文档**（career-emulator.readthedocs.io）写作 `deepseek-v4.1-flash`
> - 参赛仓库的 `.env.example` 写作 `deepseek-v4-flash`
>
> **以官方文档为准**，填 `deepseek-v4.1-flash`。云端正式评测统一使用 DeepSeek-V4.1-Flash，本地用不同模型会导致成绩不可比。

`.env` 只在仓库根目录维护，`make setup` 会自动把这三个变量**覆盖写入** JiuwenSwarm 命名实例的环境文件（仅覆盖同名键，不动其它配置）。

## 三、完整命令流程

```bash
# ── 进入仓库 ────────────────────────────────────────────────
cd "<PROJECT_ROOT>/CareerSim-BDCI26"

# ── 1. 安装依赖（career-emulator[bdci] + jiuwenswarm + 工具链）──
make sync                    # 等价于 uv sync

# ── 2. 配置环境 ─────────────────────────────────────────────
cp .env.example .env
# 用编辑器填好 API_BASE / API_KEY / MODEL_NAME
make setup                   # 创建 career_emu 实例 + 写 MCP 配置 + 同步 .env

# ── 3. 启动 JiuwenSwarm（在独立终端常驻运行）─────────────────
make start-jiuwen            # = uv run jiuwenswarm-start --name career_emu all
# 前端 UI: http://localhost:6173

# ── 4. 跑一局 ───────────────────────────────────────────────
make play                    # 挂载 solution/ 的技能，驱动一局完整对局

# ── 5. 查看结果 ─────────────────────────────────────────────
make score                   # 重新读取结局分
make replay                  # 从 events-*.jsonl 生成 Markdown 战报
```

### 查看实例状态

```bash
uv run jiuwenswarm-start --list
```

输出示例：

```
INSTANCE     STATUS     PID     WORKSPACE                                      PORTS
default      stopped  -       <~/>.jiuwenswarm                        18092/19000/19001/5173
career_emu   running  58987   <~/>.jiuwenswarm-instances/career_emu   19092/20000/20001/6173
```

`PORTS` 最后一列是前端端口；第一列 `19092` 是 AgentServer 的 WebSocket 端口（runner 自动解析）。

## 四、提交件校验与打包

```bash
# 校验提交件布局 + manifest 字段 + 每个 SKILL.md 的 frontmatter
uv run python -m career_sim_runner validate --submission solution

# 也可以只做提交件检查（不检查运行环境）
uv run python -m career_sim_runner validate --submission solution

# 打包（交付件是单个 zip）
cd solution && zip -r ../career-sim-agent.zip . -x '.*' && cd ..
```

**zip 内目录结构必须是：**

```
manifest.json
README.md
design/skills_design.md
design/decision_report.md
skills/<skill-id>/SKILL.md
...
```

> 打包时不要在 zip 里再套一层 `solution/` 目录（以官方说明为准，稳妥做法是保持与其他选手一致的「解包后即 `manifest.json` 在根」结构；若平台要求包含 `solution/` 目录，则按平台提示调整）。

### runner 的全部子命令

| 命令 | 作用 |
| --- | --- |
| `setup` | 显示配置路径、工具可用性、推荐配置 |
| `validate --submission <dir>` | 校验提交件 + 本地环境（返回码 0 = 通过） |
| `install --submission <dir>` | 把提交件安装进 JiuwenSwarm |
| `play --submission <dir>` | 安装 + 驱动一局 + 评分（`--continue` 续局，`-q` 静默） |
| `score` | 重读上次运行的结局分 |
| `replay [--events <path>] [--live] [--wait N]` | 生成/实时渲染战报 |

## 五、不发 Agent 也能玩（手动试玩，用于熟悉规则）

想先搞懂规则而不烧 Token，可以直接用 CLI 手动玩：

```bash
# 在已 sync 的仓库目录内
uv run career-emulator play
```

CLI 内可用指令：
- 输入**数字** → 执行对应选项
- 输入 `handbook` → 随时翻新员工手册
- 输入 `logs` → 查看当前会话日志
- 输入 `quit` → 退出

更新数据集（本地 Dev 剧本）：

```bash
uv run career-emulator update --source distribution   # 用 PyPI 包内的 dev 剧本
uv run career-emulator update --source github         # 从远端仓库克隆
uv run career-emulator update --split dev             # 指定 split
```

## 六、让其他 Agent 接入（可选）

除 JiuwenSwarm 之外，任何支持 MCP 的 Agent 都可以接入：

```bash
career-emulator-mcp                  # stdio 模式
career-emulator-mcp --transport http --port 8000 --path /mcp   # HTTP 模式
career-emulator-mcp -c               # 竞赛模式（只允许开一局）
```

支持 **MCP Bundle（`.mcpb`）** 的客户端（如 Claude 桌面版）可双击 `career_emulator.mcpb` 直接安装。

**MCP 服务端相关环境变量**（`make setup` 已自动写入实例配置）：

| 变量 | 含义 | 默认 |
| --- | --- | --- |
| `CAREER_EMULATOR_DB` | SQLite 会话库路径 | 仓库内 `.career_sim_runner/career_emu/career_emulator.sqlite3` |
| `CAREER_EMULATOR_LOG_DIR` | 模拟器日志目录 | 同上 `/emulator_logs` |
| `CAREER_EMULATOR_MONTHLY_EVENT_LIMIT` | 每月事件上限 | **3** |
| `CAREER_EMULATOR_ACTIVE_LONG_CHAIN_LIMIT` | 同时活跃长链上限 | **1** |
| `CAREER_EMULATOR_MAX_NOTE_LENGTH` | `notes` 最大长度 | **1000** 字符 |
| `CAREER_EMULATOR_DATASET` | 剧本 split（dev / test / …） | dev |

> `take_action` 的 `notes` 参数上限 1000 字符，超出会被截断。写决策理由时注意长度。

## 七、故障排查

| 现象 | 原因与处理 |
| --- | --- |
| `make setup` 报 `career-emulator[mcp] is not installed in the same environment` | `career-emulator-mcp` 与 `jiuwenswarm-start` 不在同一环境。**必须用 `uv run` 前缀**，不要把包装进全局 Python |
| `backend-reachable` 校验失败 | JiuwenSwarm 实例未启动。先在独立终端 `make start-jiuwen` |
| `JiuwenSwarm does not seem to have instance 'career_emu'` | 未执行 `make setup`，或实例被删。重跑 `make setup` |
| `Missing submission manifest.json` | `solution/` 下缺 `manifest.json` |
| `manifest.json 'team' is ... — replace it with your actual team name` | 队名仍是占位符 |
| `SKILL.md: missing YAML frontmatter` | 文件第一行必须是 `---`（前面不能有空行/BOM） |
| `Dataset split 'dev' not found` | 未安装 `career-emulator-bdci26` 或 split 名写错。跑 `uv run career-emulator update --source distribution` |
| Windows 上中文乱码 | 终端编码问题；runner 已做 UTF-8 重配置，仍异常可用 `chcp 65001` |
| `play` 中途长时间无输出 | 单局最长 7200 秒（2 小时）超时上限；属正常，用 `make replay` 实时观察进度 |

## 九、重新解码数据集（若官方更新了数据包）

```bash
cd "官方资料"
uv run --with msgpack python decode_dataset.py
```

脚本逻辑与模拟器一致：`msgpack.loads(zlib.decompress(data[1:], wbits=-15))`。
