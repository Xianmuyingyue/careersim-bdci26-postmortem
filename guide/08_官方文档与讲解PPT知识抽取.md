## 二、★ 冲突裁决：`manifest.json` 的 `mode` 到底能填什么

这是三份材料互相打架的地方，必须先定论，否则提交会被直接拒绝。

| 来源                                        | 说法                                                                    |
| ----------------------------------------- | --------------------------------------------------------------------- |
| 赛题仓库 `README.md:153–158`                  | `agent` / `team`                                                      |
| readthedocs `quickstart.html`             | `agent` / `team`                                                      |
| **讲解 PPT**                                | **`agent.plan`（规划）/ `agent.fast`（快速）/ `team`（团队协作）**                  |
| Runner 源码 `constants.py:27`               | `SUPPORTED_RUN_MODES = frozenset({"agent", "team"})`                  |
| **JiuwenSwarm 源码** `slash_command.py:118` | `agent｜code｜team｜**agent.plan**｜**agent.fast**｜code.plan｜code.normal` |

### 裁决

**两边的说法都是对的，只是层级不同：**

- **`agent.plan` / `agent.fast` 确实是 JiuwenSwarm 的真实运行模式**（框架源码里有），PPT 没有错；
- 但**赛题 Runner 在 `ws_client.py:139–146` 会拦一道白名单**：
  ```python
  mode = str(install_record.manifest.get("mode") or "NOT GIVEN").strip()
  if mode in SUPPORTED_RUN_MODES:   # {"agent", "team"}
      return mode
  raise SubmissionError(f"Unsupported JiuwenSwarm agent mode: {mode}")
  ```

**⇒ 结论：本地与当前云评测版本都必须填 `agent`。**

填 `agent.plan` 会导致 `make play` 直接抛 `SubmissionError`，**本地连跑都跑不起来**。  
如果后续官方放行新版 Runner，再考虑切 `agent.plan`（规划模式可能更利于长程决策）——但现在不要冒险。

### 一条附带风险：`MODEL_NAME` 文档与实测不符

readthedocs 两处都写「本地开发时请将 `MODEL_NAME` 设为 `deepseek-v4.1-flash`」，  
但 2026-09-24 实测 DeepSeek API **直接拒绝该名称**：

```
The supported API model names are deepseek-flash, deepseek-v4-pro,
but you passed deepseek-v4.1-flash.
```

**⇒ 必须保持 `.env` 里 `MODEL_NAME="deepseek-flash"`**，文档值照抄会连不上模型。  
（详见项目记忆中的「硬约束」条目。）

## 三、★ 核心资产：公开文档 vs 引擎实测的信息差

**这一节是本次抽取最有价值的部分。** 官方文档在多处**刻意只给方向、不给数值**，  
而这些数值我们已经从引擎数据集里挖到了。信息差即分数。

| 项目         | 公开文档给的说法                      | 引擎实测真相                                                                | 我们因此能做什么                                |
| ---------- | ----------------------------- | --------------------------------------------------------------------- | --------------------------------------- |
| **处理历史埋雷** | 「**无**（或有不可见的组织影响）」           | `HiddenRisk −1`（2 体力）                                                 | 唯一可见的精确风险治理手段；若无此信息，理性 Agent 会**永不使用它** |
| **低调避险**   | 只写 `Health +`                 | `Health +1, **HiddenRisk −1**`                                        | 把它当**风险工具**用，不是补血工具                     |
| **绩效奖金**   | `+2 / +1 / 0 / −1 / −2`（含义模糊） | `S≥12→×3.0`、`A≥8→×1.5`、`B≥5→×0.5`、`C≥3→×−1.0`、`D<3→×−2.0`（**基础月薪倍数**） | 精确推演财富曲线；且阈值 12/8/5/3 可**反推绩效分区间**      |
| **晋升阈值**   | 「具体阈值不公开，需要自己推断」              | 完整 9 级门槛表（见附录 A）                                                      | 精确冲刺，不必猜                                |
| **结局权重**   | 「较多 / 偏多 / 适中 / 有一定占比」        | `30% / 20% / 15% / 15% / 10% / 10%` + 归一化区间                           | 精算最优路径（见 `07_` 文档的 S 级测算）               |
| **组织红线**   | 「内部计数、阈值、连续触发条件不展开」           | 7 条精确条件（见附录 B）                                                        | 硬约束层可写成确定性规则                            |
| **职级截断**   | **完全未提**                      | `clamp = 下一级门槛 × 1.2`，作用于 `skill/network/output`                      | 抢晋升的真正理由：**不升职就锁上限**                    |
| **爆雷代价**   | 「组织的信任额度不是无限信用卡」              | 首次：`output` 回写为 6 个月前快照 + `dignity−2` + `wealth−2`；**第二次即出局**         | 风险定价量化                                  |

> **战略含义**：一个只读公开文档的 Agent，会认为「处理历史埋雷」是无效行动、  
> 不知道「低调避险」能降风险、不知道晋升门槛、不知道有截断机制。  
> **我们比公开信息多出的这部分，就是相对其他队伍的净优势。**

## 四、★ 新增：两条可程序化解析的自然语言读数通道

官方首页反复强调「从自然语言反馈里慢慢摸」，`handbook` 也列明了隐藏项只能从  
**邮件 / 会议纪要 / 领导反馈 / 绩效结果**推断。除已发现的 HR 风险量表与谈话措辞外，  
本次从 `salary_conditions/` 挖到两条**带固定模板**的通道：

### 通道 C · 月薪播报 → 职级 + 财富双重读数

模板（`payout_text`，一字不差）：

```
本月基本工资到账：+{amount}（{level}）
```

例：`本月基本工资到账：+0.7（L4）`

**用途**：① 校验当前职级；② 确认晋升是否已在当回合生效；③ 核算财富是否落后于目标轨迹。  
**每月刷新一次**，是全局最高频的确定性读数。

### 通道 D · 半年绩效奖金播报 → 绩效档位 + 绩效分区间

模板（`payout_text`）：

```
半年绩效奖金（{label}）：{sign}{amount}
```

**这条通道的价值被严重低估**：由 `amount ÷ 该职级月薪 = 奖金系数`，  
再对照 `bonus_tiers` 即可**反推出绩效分所在区间**：

| 反推系数 | 档位 | 绩效分区间              |
| ---- | -- | ------------------ |
| 3.0  | S  | ≥ 12               |
| 1.5  | A  | 8 – 11             |
| 0.5  | B  | 5 – 7              |
| −1.0 | C  | 3 – 4              |
| −2.0 | D  | < 3 ⇒ **再出一次就炒鱿鱼** |

**⇒ 这是判断「自己离出局还有多远」的最直接信号**，且每 6 个月刷新一次，  
与晋升窗口同频——可在同一回合内同时拿到「绩效读数 + 晋升结果」。

## 五、★ 官方给出的 SKILL 拆分建议 —— 与我们的设计完全吻合

`quickstart.html` 结尾原文（策略设计指导）：

> 一个实用的 SKILL 拆分思路：
>
> - 一个 SKILL 负责**读取状态与日志，整理局势**。
> - 一个 SKILL 负责做**短中期策略判断**，平衡健康、尊严、产出和人脉。
> - 一个 SKILL 专盯**风险和失败方向**，避免队伍打着打着突然学会了什么叫职业生涯自由落体。

| 官方建议         | 我们的技能                 | 对应     |
| ------------ | --------------------- | ------ |
| 读取状态与日志、整理局势 | `situation-awareness` | ✅ 完全一致 |
| 短中期策略判断      | `decision-policy`     | ✅ 完全一致 |
| 专盯风险与失败方向    | `risk-guardian`       | ✅ 完全一致 |

**⇒ 我们的三层正交设计**（事实层 / 约束层 / 决策层）**与官方推荐拆分一字对应**。  
这应明确写进 `design/skills_design.md`，作为专家评审（占 30%）的直接得分点。

### 官方给的三条策略提醒（原文）

> - 先保证自己别太快触碰公开可见的危险边缘，比如健康、尊严、人脉和财富都不要长期摆烂。
> - **不要把所有资源都砸到单一维度**。短期数值很好看，不代表半年后绩效和晋升也会跟着一起鼓掌。
> - **看到一句自然语言反馈时，别只当文案**。很多隐藏机制不会给你公式，但会给你暗示。

官方首页的另一句：

> 规则里没写出来的内容，不代表它不存在；多数时候，它只是想等你亲自踩一次才肯露面。

`failure-and-ending.html` 的收尾句：

> 在不完全信息里，**长期维持一份不崩盘且能慢慢变好的职业轨迹**，是这一题的通关密码。

## 六、PPT 中值得单列的信息

### 6.1 一句话目标（PPT 原文）

> **信息不完全下避红线、撑满 48 月、冲等级**

### 6.2 时间循环（与引擎一致）

- **每月**：月初发基本工资 + 生成剧情事件（每月最多 3 个）→ 处理选择
- **季度末**：3 点 Energy（**不累积**）分配体力行动 + **1 个主行动（可不行动）**
- **每 6 个月**：绩效评估 + 结算绩效奖金 + **开放晋升窗口**

三条要点（PPT 原文）：

1. 剧情选择影响短期状态，也会改变后续事件走向
2. 季度行动是主动调节职业轨迹的主要抓手
3. **风险常延迟兑现，不会当月爆，往往攒着以后算总账**

### 6.3 组织红线 / 失败方向（PPT 列出 8 条）

健康归零·强制结束 ｜ 长期无尊严·隐雷爆雷 ｜ 连续低绩效 ｜ 人脉长期归零 ｜ 财富长期见底 ｜ 技能持续掉队

> 「公开筛选方向，不公开具体设定」

### 6.4 策略提醒（PPT 底部）

> 别长期摆烂健康/尊严/人脉/财富；别把资源砸单一维度；**自然语言反馈常是隐藏机制暗示**

## 七、对当前 SKILL 设计的增量改进（在 `07_` 的 7 条之上）

| #  | 改进                                                                                                                                            | 依据                                                 |
| -- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 8  | **`risk-guardian` 增补「低调避险」的隐藏效果** —— 当前技能只把它当 `Health+1` 的血包，应升级为「`HiddenRisk −1` 的风险工具」，在 `hidden_risk ≥ 2` 且非冲刺季时优先于「处理历史埋雷」（前者免费、后者耗 2 体力） | 公开文档隐去了 `HiddenRisk −1`，而它使低调避险成为**零成本降风险**选项      |

| 13 | **`.env` 保持 `MODEL_NAME="deepseek-flash"`**                                                                                                   | 文档推荐的 `deepseek-v4.1-flash` 会被 API 拒绝              |
